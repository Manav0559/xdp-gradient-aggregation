$ netsum — live protocol demo

Watch workers' gradients get summed inside the network, lose packets, recover, and fall back to the parameter server.

This page runs a JavaScript simulation of NetSum's protocol rules (slot state machine, resend flush, TTL sweeper, collision fallback, merge by contributor set, wire v3 exponents) as described in docs/DESIGN_NOTES.md. The real system is C and an XDP program in the Linux kernel, tested in CI; its measured results are on the results dashboard.

Aggregator slot pool

Each key (round, chunk) hashes to one slot. A slot owned by another key sends the contribution on to the parameter server as a fallback. ACCUMULATING → COMPLETED when every worker's bit is set; a RESEND for a held worker flushes the partial sum (FLUSHED); the parameter server's ACK, or the TTL sweeper, frees the slot.

What to try

  • Gradient size ~1e-4 with v2: Q16.16 has a resolution of 2^-16, so most values round to 0 and the received sums are wrong. Switch to v3: each chunk carries its own exponent, chosen from the previous round's result, and the sums become accurate.
  • Raise packet loss: workers retransmit with RESEND; the aggregator flushes partial sums, the remaining contributions fall back to the parameter server, and it merges them by contributor set. Every result still matches the exact integer sum.
  • Fewer aggregator slots: keys collide more often and more traffic falls back to the parameter server.
  • Spike (v3): every chunk saturates, comes back OVERFLOW, and is retried in the same round at exponent − 8 under a new key.

Correctness check: the "exact" counter compares every result a worker receives with the integer sum of all workers' quantized values for that key, computed independently. Simplifications: one job, chunks of 4 values, loss only on worker links, and timings scaled to be watchable.
