// 01 · packet reduction

Aggregator-uplink traffic: no-aggregation vs. userspace aggregation

In noagg, every worker's contribution reaches the parameter server individually. In useragg, the aggregator absorbs every partial contribution (never forwarded — the same XDP_DROP behavior the real kernel program uses, verified on a live Linux kernel in CI) and emits exactly one summed packet once the slot is complete. This is ATP's core mechanism, measured here against the userspace baseline while the XDP path's own latency number (below) is still pending.

// 03 · latency distribution rigor

Percentiles, bootstrap confidence, and significance — not just mean/min/max

Mean/min/max over a handful of trials is exactly the setup prone to tail-latency effects (the userspace aggregator is explicitly single-threaded — one OS-scheduling gap shows up as a tail outlier, not a shifted mean) and to noise at low trial counts. This panel reads bench/results_percentiles.csv (written by scripts/benchmark.py from the same real per-trial runs as the chart above, now at 30 trials per cell): p50/p95/p99 per config, a bootstrap 95% confidence interval on the median (whiskers on the p50 bars below), and a permutation test — using Cliff's delta as a distribution-free effect size, the same quantity a Mann-Whitney U test's statistic reduces to (delta = 2U/(n·m) − 1) — comparing noagg vs. useragg latency at each worker count. Plain Python throughout (resampling loops, no SciPy/NumPy dependency).

// 04 · multi-tenant fairness — Jain's index

Formal fairness sweep: does the admission quota actually equalize access?

ATP's own paper title is literally "...for Multi-tenant Learning" — its headline contribution, previously proven here only qualitatively (one test, one greedy job, one rejected round). scripts/fairness_sweep.py drives 3 concurrent synthetic jobs with deliberately uneven concurrent-slot demand (16 / 4 / 8, via the same "worker 1 never sends, so the slot never frees" technique the correctness suite already uses) at a fresh bin/agg for each max_slots_per_job quota value, snapshots each job's live slot-table occupancy via a real SIGUSR1-triggered stats dump, and computes J = (Σxᵢ)² / (n·Σxᵢ²) over each job's concurrent_slots — its actual share of the shared resource at that moment, not its own admitted/attempted ratio (that ratio is trivially 1.0 whenever quota=0, which would make "unlimited" look perfectly fair — the opposite of the point). Every quota's outcome here reran identically across 3 repeats — real, deterministic measurements, not simulated.

// 05 · project status

What's built, tested, and pending

Every checked item below is backed by a real, runnable command in this repo — nothing here is aspirational.

  • [x]Wire protocol (protocol/grad_proto.h) — Q16.16 fixed-point, network byte order, shared by every component
  • [x]Worker + parameter server (baseline #1, no-aggregation) — make && python3 tests/test_correctness.py, 10/10 passing
  • [x]Userspace aggregator (baseline #2) — same slot/accumulate/emit algorithm the XDP program will run, packet-reduction verified (N→1)
  • [x]Two real bugs found and fixed during testing: duplicate-worker double-counting, and a select()-vs-buffered-I/O race in the test harness itself
  • [x]XDP/eBPF kernel program (xdp_agg/xdp_agg.c) — compiles to valid eBPF bytecode (make bpf); a real BPF-stack-limit bug was caught and fixed at this stage
  • [x]Independent adversarial code review found 10 confirmed issues (2 critical: an out-of-bounds-write risk in the write-back path, and a missing packet-length check in the userspace baseline) — all fixed and regression-tested, see xdp_agg.c's header comment for the full list
  • [x]Real-kernel verification — xdp_agg.o loaded on a real Linux kernel in CI (xdp-loadtest.yml), verifier-accepted, and driven with real UDP traffic across a veth pair including every adversarial input; the real verifier rejected the original object over a loop bounds-proof gap codegen alone could never catch — fixed and now green
  • [x]Multi-tenant fairness — ATP's actual headline contribution ("...for Multi-tenant Learning"): a per-job admission quota in userspace_agg/agg.c caps concurrently-incomplete slots per job_id, proven to isolate a greedy job from starving others via a dedicated regression test
  • [x]Slot-table TTL/reaper — closes the crashed-worker resource leak the fairness quota alone doesn't cover: an incomplete slot with a genuinely dead worker is now evicted after a configurable timeout instead of leaking forever, proven via a dedicated regression test
  • [x]Differential fuzz harness (fuzz/) — adversarially searches for divergence between the userspace and XDP admission-check logic instead of relying only on hand-written tests; 133M CI executions, zero crashes, zero divergences found
  • [x]Formal Jain's-fairness-index sweep (scripts/fairness_sweep.py) — quantifies the per-job admission quota's actual fairness across 3 concurrent jobs with uneven demand instead of just proving the mechanism fires once, via a real SIGUSR1-driven stats dump added to userspace_agg/agg.c
  • [x]Latency-distribution rigor (scripts/benchmark.py) — p50/p95/p99, a bootstrap 95% CI on the median, and a permutation test (Cliff's delta effect size) comparing noagg vs. useragg at each worker count, over 30 trials per cell instead of mean/min/max over 10
  • [x]Fairness quota ported into the XDP kernel program itself (job_quota_map) — a real, loaded, verifier-accepted greedy job is rejected on its 3rd concurrent slot against a quota of 2 while a second job completes unaffected; a real netem sweep confirms the program still aggregates correctly under 20% packet loss and reordering, and empirically confirms the known no-TTL gap: a slot stuck by permanent packet loss leaks in slot_map rather than silently recovering
  • [ ]A kernel-side TTL/reaper (needs bpf_timer, Linux 5.15+) to close the leak the netem sweep just confirmed, and real per-packet XDP latency numbers via BPF_PROG_TEST_RUN
