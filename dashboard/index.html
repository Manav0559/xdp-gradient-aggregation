// 03 · cost per packet

Where the time goes: ns per packet

XDP: run_time_ns / run_cnt (time inside the BPF program). Userspace: the aggregator's algorithm alone (agg --profile) and its whole on-CPU time per packet including system calls. Not like-for-like: neither includes the receive path before the hook or socket.

Training loss through every aggregation path

// 06 · environment and caveats

What produced these numbers, and what they cannot show

Loading…

GitHub-hosted runner: a shared 4-vCPU VM. veth is a software device (no NIC, no DMA); generic XDP still allocates an skb; workers, aggregator and parameter server share one host. Relative comparisons within one run are the meaningful output, not absolute packet rates. Nothing here is a line-rate claim.

// history

v1 (macOS loopback)

The v1 benchmark launched workers one after another on macOS loopback, so its latency mostly measured process start-up, and it did not include the XDP path. Its data is kept in bench/v1-macos-loopback/; see docs/HISTORY.md.

Data: bench/v2/summary_throughput.csv, summary_latency.csv, comparisons.csv, fairness_summary.csv, environment.json (CI run 43765091283) and examples/train_mlp/results/curves.csv (CI run 43784240658). This page computes nothing; it parses and draws those files.
