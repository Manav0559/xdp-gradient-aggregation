// 01 · packet reduction

Aggregator-uplink traffic: no-aggregation vs. userspace aggregation

In noagg, every worker's contribution reaches the parameter server individually. In useragg, the aggregator absorbs every partial contribution (never forwarded — the same XDP_DROP-shaped behavior the eventual kernel program uses) and emits exactly one summed packet once the slot is complete. This is ATP's core mechanism, reproduced here in userspace before the kernel version exists.

// 03 · project status

What's built, tested, and pending

Every checked item below is backed by a real, runnable command in this repo — nothing here is aspirational.

  • [x]Wire protocol (protocol/grad_proto.h) — Q16.16 fixed-point, network byte order, shared by every component
  • [x]Worker + parameter server (baseline #1, no-aggregation) — make && python3 tests/test_correctness.py, 10/10 passing
  • [x]Userspace aggregator (baseline #2) — same slot/accumulate/emit algorithm the XDP program will run, packet-reduction verified (N→1)
  • [x]Two real bugs found and fixed during testing: duplicate-worker double-counting, and a select()-vs-buffered-I/O race in the test harness itself
  • [x]XDP/eBPF kernel program (xdp_agg/xdp_agg.c) — compiles to valid eBPF bytecode (make bpf); a real BPF-stack-limit bug was caught and fixed at this stage
  • [x]Independent adversarial code review found 10 confirmed issues (2 critical: an out-of-bounds-write risk in the write-back path, and a missing packet-length check in the userspace baseline) — all fixed and regression-tested, see xdp_agg.c's header comment for the full list
  • [x]Multi-tenant fairness — ATP's actual headline contribution ("...for Multi-tenant Learning"): a per-job admission quota in userspace_agg/agg.c caps concurrently-incomplete slots per job_id, proven to isolate a greedy job from starving others via a dedicated regression test
  • [x]Slot-table TTL/reaper — closes the crashed-worker resource leak the fairness quota alone doesn't cover: an incomplete slot with a genuinely dead worker is now evicted after a configurable timeout instead of leaking forever, proven via a dedicated regression test
  • [ ]XDP program load-tested against the real in-kernel verifier and run on a live interface — needs a real Linux kernel (see docs/DEV_ENVIRONMENT.md for why this dev machine can't do it directly)
  • [ ]Porting the fairness quota and TTL reaper into the XDP kernel program itself, a formal Jain's-fairness-index sweep across concurrent jobs, and the full netem loss/reorder correctness sweep
